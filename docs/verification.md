# 포트폴리오 리디자인 검증 결과

검증일: 2026-10-02. 실제 브라우저에서 인트로와 상세 전환을 점검하고, 초기 레이아웃·역량 클릭·상세 위치 복귀를 보완했다. 기존 `feat/dean-portfolio-redesign` 브랜치에서 구현했으며, 사용자의 후속 요청에 따라 `feat/portfolio-redesign-motion-polish` 브랜치로 변경을 기록한다. 운영 배포는 포함하지 않는다.

## 구현 범위

프론트엔드 개발자 이정민의 소개와 문제 해결 경험을 중심으로 구성했다. 대표 작업은 오피스너 앱·웹, 앱 업데이트 관리, fastlane 빌드·배포, Sentry 오류 관측의 5개 사례다. 경력·교육 사례 16개를 보존해 공개 상세는 총 21개다. 운영하지 않는 Pic a note·OMOMO·기존 개인 포트폴리오는 공개 목록·상세·사이트맵에서 제외했으며 원본 자료는 보존했다.

Taste 디자인 스킬을 적용해 디자인 변화 8·모션 9·정보 밀도 3으로 다듬었다. 기존 팔레트와 로컬 폰트를 유지하고, 구분선을 최소화해 배경과 여백으로 섹션을 나눴다. 큰 제목·먹색 성과 영역·가로 전환되는 역량 장면으로 인상을 강화하고 작은 푸터와 반복 장식 아이콘을 줄인 구성을 유지했다. 최신 내비게이션은 작업·성과·역량·소개·경력·연락으로 구성하며 현재 섹션을 표시한다.

메인에는 전체 프론트엔드 역량과 확인된 개발 범위 3개를, 대표 상세에는 성과 지표 5개를 표시한다. 메인은 SI 프로젝트 8개·키보드 처리 이관 14곳·RN 버전 전환 2단계이며 개선율을 뜻하지 않는다. 문구 중심의 AS-IS·TO-BE 비교는 제거했다. 상세의 개선 전·후 값과 변화량, 단위, 측정 기준·기간·출처를 함께 관리하며 현재 성과 수치는 모두 `null`, 상태는 `pending`이다. 확인되지 않은 값은 `—`로 표시하고 `verified` 상태의 값만 공개한다. 후속 수치 입력 위치와 검증 절차는 [콘텐츠 근거](./content-evidence.md)에 기록했다. 확인하지 않은 성과 수치·단독 개발·운영 배포 완료를 주장하지 않았다.

## 모션과 상세 탐색

- 제목 두 줄은 첫 표시부터 CSS 마스크 안에서 순차적으로 올라온다. 인트로 높이를 초기 렌더부터 고정해 hydration 점프와 제목 재등장을 제거했으며, 스크롤에 따라 최대 1.5배까지 확대된 뒤 마지막 크기를 유지하며 다음 섹션으로 이어진다. 성과 영역의 큰 배경 글자와 지표는 서로 다른 속도로 움직인다.
- 역량 패널 3개는 CSS sticky로 표시 영역을 고정하고 세로 스크롤에 따라 가로 이동·확대·축소된다. 사용자 경험·시스템·출시 이후 개선을 도식과 이미지로 보여 준다. 키보드 포커스가 이동하면 해당 패널을 표시하며 벽돌색 패널에는 종이색 포커스 외곽선을 사용한다. 상세 열기나 창 크기 변경으로 본문 폭이 달라지면 이동 거리를 다시 계산한다. 역량을 읽는 중 창 크기·모션 설정이 바뀌어도 포커스 링크를 다시 표시하며, 다른 섹션으로 스크롤한 뒤에는 현재 읽기 위치를 유지한다.
- 작업 카드는 마우스 위치를 따라 입체적으로 기울고 주요 버튼은 포인터 위치에 반응한다. 연속 값은 MotionValue로 처리하며 터치에는 포인터 이동 효과를 적용하지 않는다.
- 작업 필터는 카드 위치만 이동해 재배치한다. 상세는 16px 이동·0.36초, 본문은 8px 이동·0.32초로 등장한다. 본문 전체 FLIP을 제거해 글자가 비균등 확대되지 않도록 했다.
- 1024px 이상에서는 상세 너비를 `clamp(360px, 32vw, 600px)`로 제한한다. 1024px에서는 메인 약616px·상세 360px, 1440px에서는 메인 약931px·상세 약461px를 확보한다. 상세는 자체 스크롤을 사용하며 메인 필터를 유지한다.
- 1023px 이하에서는 메인 다음에 상세를 일반 본문으로 배치한다. 배경 잠금·오버레이·모달은 사용하지 않는다.
- 닫기·Escape·브라우저 히스토리 이동에서 메인의 카드 포커스와 스크롤, 각 사례의 읽던 위치를 복원한다. 창 너비를 왕복해도 상세의 읽던 위치를 보존한다. 다른 섹션으로 이동할 때와 직접 `/#work` 진입 시에는 최종 레이아웃에서 목적지 앵커를 따른다.
- 상세 URL은 유지한다. 직접 진입·새로고침·독립 상세의 다음 사례 링크는 독립 페이지로 제공한다.
- 시스템 동작 줄이기 또는 화면 높이 740px 미만에서는 인트로와 역량 패널을 일반 흐름으로 표시한다. 동작 줄이기에서는 지속되는 이동과 부드러운 스크롤도 제거한다. JavaScript 없이도 소개·개발 경험·전체 역량·독립 상세를 읽을 수 있다.

## 후속 인트로 스크롤 조정

인트로는 표시 영역과 본문 크기를 측정해 최대 1.5배까지 계속 확대한다. 제목·설명·버튼이 잘리지 않도록 화면에 맞춰 상한을 조절하고, 짧은 데스크톱 화면에서는 제목 크기와 여백을 줄여 확대 공간을 확보했다. 시작과 끝의 확대 속도는 `easeInOut`으로 완화하며, 최대 크기에서는 기존 sticky가 해제되어 다음 성과 섹션으로 이어진다. 크기 변경은 ResizeObserver로 반영하고, 시스템의 동작 줄이기 또는 낮은 화면에서는 기존 정적 배치를 유지한다.

390·1440px 회귀 검사에 30% 이상 확대와 본문 전체 가시성을 추가해 기존 12% 확대에서 두 검사가 실패하는 것을 확인했다. 320×740·1440×740px 경계 검사도 추가했으며 수정 후 전체 76개가 통과했다. Chromium의 7개 화면에서 실제 확대 크기는 320×740px에서 1.156배, 390×844px에서 1.382배, 1440×740px에서 1.345배, 1440×900px에서 1.379배, 980×844·1440×1000px에서 1.5배였다. Firefox·WebKit에서도 모바일·짧은 데스크톱·큰 데스크톱의 표시 영역과 휠 입력 후 최대 크기 유지를 확인했다. 독립 검토에서 320~1920px 및 높이 840·841px 경계, 연속 창 크기 변경과 동작 줄이기 전환에서도 잘림·가로 넘침·ResizeObserver 반복 오류가 없었다.

2026-10-02에는 초기 표시의 레이아웃 점프·제목 재등장, 역량 링크 클릭 중 이동, 앵커 오차와 상세 위치 소실을 추가 수정했다. 모바일 메뉴 밖으로 포커스를 옮길 때 메뉴가 링크를 가리는 문제와 텍스트 200% 확대 시 역량 콘텐츠 잘림은 이번 모션 수정에서 다루지 않았다. 자동 접근성 검사 통과는 이 두 문제의 해결을 의미하지 않는다.

이전 확대 폭 수정의 검증 로그는 `/tmp/dean-hero-large-build.log`, `/tmp/dean-hero-large-tests.log`에, 브라우저 수치와 화면은 `/tmp/dean-hero-large/`에 기록했다. 확대 폭 변경 전 실패 기록은 `/tmp/dean-hero-large-red.log`이다. 이전 12% 확대 구현의 검증 자료는 `/tmp/dean-hero-growth/` 및 같은 이름의 빌드·테스트 로그에 남겨 두었다.

## 2026-10-02 상세 전환과 모션 점검

기존 상세 전환에서 1440px 본문 폭이1440→835px로 약42% 줄고, 전체 FLIP의 `scaleX≈1.71`·`scaleY≈0.94`가 글자를 비균등하게 변형했다. 클릭 카드도 화면 top250px에서 최저−926px까지 이동했다. 전체 scale을 제거하고 패널 너비를 제한했으며, 절대 scrollY 대신 카드의 화면 위치와 역량 진행률로 복귀점을 계산한다. 레이아웃이 안정될 때까지 보정하고 휠·터치·키보드 입력이 들어오면 즉시 보정을 중지한다.

Chromium 1440×1000·1920×1080에서는 본문 scaleX/Y가 전 프레임1, 카드 최대 이동0.49px·0.05px였으며 닫기 후 원래 위치로 돌아왔다. 1100×900·390×844에서는 일반 문서 상세가 표시되며 닫기 후 카드 위치도 복원됐다. 네 화면의 상세 캡처를 직접 확인했다.

수정 전 일반 모션 검사에서 전체 main scale 오차0.639, 상세에서 헤더 이동 오차989.9px, 직접 작업 앵커 진입 오차2172.1px, resize 뒤 상세 top3310.2px를 기록했다. 역량30·40% 위치의 포인터 클릭도 이동에 실패했다. 해당 회귀4개와 포인터2개, 느린 JS 초기화·정적 인트로5개를 추가했다. 가로 sticky 장면의 이미지 검사는 이미지의 해당 장면으로 실제 이동한 뒤 로딩을 확인하도록 보완했다.

독립 Firefox·WebKit 점검에서 글자 비율·카드 위치, 역량 링크 포인터 클릭과 상세 읽기 위치를 확인했다. WebKit에서 상위 main과 하위 역량을 중복 관찰하면 ResizeObserver 오류가 발생하는 것을 별도 실패 검사로 재현했다. 하위 역량 측정이 상위에 레이아웃 변화를 알리도록 연결해 같은 프레임의 위치 보정을 유지했다. 최신 두 엔진의 열기·닫기·역량 클릭·창 너비 왕복에서 pageerror0건, 카드 이동0.5px 미만, 상세 스크롤 복원799~800px를 확인했다.
