# DEAN 포트폴리오 리디자인 계획과 진행 기록

## 목표와 범위

채용 담당자가 프론트엔드 개발자 이정민의 제품 개발 역량과 문제 해결 방식을 빠르게 파악하도록 기존 Next.js 포트폴리오를 리디자인한다. 기존 `feat/dean-portfolio-redesign` 브랜치에서 구현했으며, 사용자의 후속 요청에 따라 전체 변경을 `feat/portfolio-redesign-motion-polish` 브랜치에 커밋·푸시한다. 운영 배포는 포함하지 않는다.

메인 소개는 특정 앱 개발보다 사용자 경험·서비스 안정성·개발 생산성을 아우르는 전체 역량을 강조한다. 대표 작업은 오피스너 웹·앱과 업데이트 관리·fastlane 빌드 및 배포·Sentry 오류 관측의 5개 사례로 구성한다. 에너지 대시보드·관리자 초기 설정·공통 UI·개인 프로젝트는 대표 목록에 별도로 배치하지 않는다.

사용자의 최신 요청에 따라 문구 중심의 AS-IS·TO-BE 비교 화면을 정량 성과 레이아웃으로 교체한다. 아직 이력서와 측정 근거가 정리되지 않았으므로 임의의 수치를 넣지 않고 확인 예정 슬롯을 먼저 제공한다. 큰 타이포그래피와 스크롤·포인터 모션으로 시각적 인상을 강화한다.

## 디자인과 구조

- Taste 디자인 스킬을 적용하고 디자인 변화 8, 모션 9, 정보 밀도 3을 기준으로 한다. 편집 디자인과 워크웨어의 투박함을 유지하면서 큰 제목·넉넉한 여백·대비가 강한 패널로 읽기 편한 구성을 만든다.
- 종이색 `#E8E4D9`, 먹색 `#272B25`, 올리브 `#566348`, 벽돌색 `#A64D37`을 사용한다. 작은 글자의 대비를 위해 `#536046`, `#8F412D` 텍스트 토큰을 사용한다.
- Pretendard와 Barlow Condensed를 로컬에서 제공하며 폰트 라이선스를 함께 보관한다.
- 구분선과 반복되는 장식 아이콘은 최소화하고 배경색·여백·타이포로 섹션과 정보 위계를 구분한다. 푸터는 작게 유지한다.
- 메인 순서는 소개 → 정량 성과 → 역량 패널 → 대표 작업 → 개발 방식과 기술 → 경력·교육 → 연락이다. 내비게이션은 작업·성과·역량·소개·경력·연락이며 현재 섹션을 표시한다.
- 역량 패널은 사용자 경험, 복잡한 시스템 흐름, 출시 이후 개선의 세 관점으로 구성하고 관련 사례로 연결한다.
- 대표 사례의 필터는 `전체`, `앱 개발`, `웹 개발`, `업데이트·운영`의 4개다. 앱과 웹 사례는 같은 위계로 배치한다.
- `/work/[slug]` 상세는 문제·정량 성과 슬롯·접근 방식·개인 기여·기술·관련 화면을 제공한다. 홈에서 선택하면 오른쪽 인라인 본문으로 열고, 직접 URL 진입과 새로고침은 독립 상세로 제공한다.
- 스티브랩스 8개·원티드 코스 8개는 경력·교육에서 열람한다. 운영하지 않는 Pic a note·OMOMO·기존 개인 포트폴리오는 공개 목록·상세 경로·사이트맵에서 제외하고 원본 자료와 이미지는 보존한다.
- 기존 개인 이메일의 메일 보내기·주소 복사와 GitHub·블로그를 제공한다.

## 정량 성과 레이아웃

- `assets/portfolio.ts`의 `ImpactMetric` 모델에 개선 전·후·변화량, 단위, 확인 상태, 측정 기준·기간·출처와 개인 기여를 함께 보관한다.
- 메인은 `experienceMetrics`의 SI 프로젝트 8개·키보드 처리 14곳·RN 버전 전환 2단계로 개발 경험을 보여준다. 각 대표 사례의 `impactMetrics`는 로그아웃 대기 시간·앱 연결 완료율·OTA 업데이트 성공률·빌드 및 배포 시간·오류 원본 위치 확인 비율을 다룬다.
- 개발 경험 카드는 확인된 작업 범위와 설명을 표시한다. 상세의 성과 수치는 현재 `null`, 상태는 `pending`이다. `ImpactMetrics`는 `verified` 상태의 값만 표시하고 나머지는 `—`와 `수치 확인 예정`으로 표시한다. 값만 입력하고 상태를 확인하지 않으면 숫자는 공개되지 않는다.
- 이력서와 동일 조건의 측정 자료를 정리한 뒤 값·단위·기간·출처를 입력하고 개인 기여 범위를 확인한다. 실제 검증을 마친 지표만 `verified`로 변경한다. 후속 입력 절차는 `docs/content-evidence.md`에 기록한다.
- 이전 `transformation` 데이터는 확인된 구현 변경의 근거로 보존하지만 화면의 비교 컴포넌트에서는 사용하지 않는다.

## 구현 원칙과 모션

- 정적 Server Component를 기본으로 사용한다. `Home`과 `ImpactMetrics`에서 콘텐츠를 구성하고 클라이언트 모션 컴포넌트에 children으로 전달한다. 메뉴·필터·주소 복사·포인터 및 스크롤 모션·인라인 상세 전환을 클라이언트 단위로 분리한다.
- 제목 마스크 등장은 CSS로 첫 표시부터 적용하며, Motion 13으로 첫 화면의 연속 확대, 성과 영역의 큰 배경 글자와 지표 이동, 필터 위치 재배치와 상세의 짧은 이동을 구현한다. 상세 열기에서 본문 전체 scale은 사용하지 않는다. 인트로는 마지막 크기를 유지하며 다음 섹션으로 이어진다. 연속되는 스크롤·포인터 값은 MotionValue를 사용한다.
- 역량 패널은 CSS sticky로 표시 영역을 고정하고 세로 스크롤을 세 장면의 가로 이동·확대·축소로 연결한다. 각 장면의 도식·이미지는 Server Component에서 구성해 전달한다. ResizeObserver로 메인 폭 변화에 맞춰 이동 거리를 계산하며, 키보드 포커스가 바뀌면 해당 장면을 표시한다. 역량을 읽는 중 창 크기·모션 설정이 바뀌어도 포커스 링크를 표시하고, 다른 섹션으로 스크롤한 뒤에는 읽기 위치를 유지한다. 작업 카드는 포인터를 따라 기울고, 주요 버튼은 포인터 위치에 부드럽게 반응한다. 터치 입력에는 포인터 이동 효과를 적용하지 않는다.
- 시스템의 동작 줄이기 설정에서는 스크롤·포인터 이동을 정적으로 제공한다. 이 설정 또는 화면 높이 740px 미만에서는 인트로와 역량 패널을 일반 흐름으로 배치한다. JavaScript 없는 초기 서버 화면에도 소개·성과 슬롯·전체 역량·독립 상세 콘텐츠를 제공한다.
- Next.js parallel·intercepting routes로 메인과 상세 URL을 유지한다. 1024px 이상에서는 상세 너비를 `clamp(360px, 32vw, 600px)`로 제한해 본문 공간을 확보하고, 1023px 이하에서는 메인 다음에 상세를 일반 본문으로 배치한다. 선택 카드의 화면 위치와 상세 읽던 위치를 보존한다.
- Git 작업 기간은 재직 기간과 구분한다. 확인되지 않은 성과 수치·단독 개발·운영 배포 완료를 주장하지 않는다. 기여 근거는 `docs/content-evidence.md`에 기록한다.
- 오피스너 이미지는 공개 소개 자료로 명시한다. 웹·OTA·fastlane·Sentry 도식은 구현 흐름을 설명하며 실제 서비스 화면이나 성과 차트로 표시하지 않는다.
- 외부 실시간 콘텐츠 조회는 추가하지 않는다. 기존 Notion 자료는 외부 문서 링크로 제공한다.
- 이전 화면 컴포넌트와 사용하지 않는 Notion·Swiper·TypeIt·Three 패키지를 제거한다. 정적 경력 데이터의 랜덤 UUID는 안정적인 ID로 교체한다.
- Next.js 15.5.26·React 19.2.8, 일치하는 ESLint 설정, sharp와 PostCSS·picomatch 보안 패치를 적용하고 pnpm 잠금 파일을 유지한다.

## 구현 기록과 현재 상태

기존 리디자인에서는 메인·대표 5개 및 경력·코스 16개 상세, 메뉴·필터·연락 기능, 메타데이터·공유 이미지·파비콘·404와 인라인 상세 이동을 구현했다. 이후 직함 통일, 작은 푸터, 장식과 구분선 축소, 개인 프로젝트 제외를 반영했다.

정량 성과 모델과 메인·대표 상세의 슬롯, 큰 인트로 제목, 대비가 강한 성과 섹션, 포인터 호버와 버튼 모션을 구현하고 이전 문구 비교 컴포넌트를 제거했다. 이후 인트로를 스크롤에 따라 확대되는 장면으로, 역량을 도식·이미지가 포함된 가로 전환 장면으로 바꾸고 섹션 내비게이션을 보강했다.

2026-10-01 재개 시 최신 코드와 이전 완료 기록의 불일치를 확인했다. 초기 Chromium 검사 68개는 통과했으나 독립 검토에서 창 크기·모션 전환 뒤 포커스가 화면 밖으로 사라지는 문제를 발견했다. 재측정 후 현재 장면의 포커스를 다시 표시하되, 다른 섹션을 읽는 중에는 스크롤 위치를 덮어쓰지 않도록 수정했다. 회귀 검사 5개를 추가했으며 최종 린트·타입·프로덕션 빌드와 Chromium 검사 73개가 모두 통과했다. 독립 재검토에서도 해당 두 문제가 해결된 것을 확인했다. 현재 동작에 맞게 문서를 갱신하고 이전 겹침 패널과 최신 가로 장면의 검증을 구분했다. 세부 결과는 `docs/verification.md`에 기록한다.

2026-10-02 후속 요청에 따라 실제 상세 전환에서 본문 폭 축소와 비균등 FLIP, 선택 카드의 큰 위치 이동을 재현했다. 본문 전체 scale을 제거하고 상세 너비를 제한했으며, 카드의 화면 위치와 역량 진행률을 기준으로 열기·닫기 위치를 보정했다. 초기 인트로 높이 점프·제목 재등장, 역량 포인터 클릭 중 링크 이동, 상세에서 헤더 앵커 이동과 직접 `/#work` 진입의 오차, 창 너비 변경 시 상세 읽기 위치 소실도 수정했다. 하위 역량 크기 측정에서 레이아웃 변화를 알리도록 연결해 Safari 엔진의 중복 ResizeObserver 오류를 방지한다. 최신 검사 결과는 `docs/verification.md`에 기록한다.

## 검증과 완료 기준

`pnpm lint`, `pnpm typecheck`, `pnpm build`가 경고·오류 없이 통과해야 한다. 실제 Chromium에서 360·390·768·1440px의 메인·대표 사례, 전체 경력·코스 사례의 상세 이동, 메뉴의 키보드 접근·Escape·닫기·이동, 필터·상세 복귀, 주소 복사 성공·거부·미지원, 연락 링크와 없는 URL·제외한 개인 사례의 404를 검사한다.

정량 지표의 확인 예정 표시와 측정 기준 열람, JavaScript 없는 콘텐츠, 인트로의 연속 확대·다음 섹션 진입과 역량 패널의 가로 전환, 키보드 탐색과 메인 폭 변화, 스크롤·포인터 모션과 동작 줄이기 설정도 확인한다. 이미지 로딩·가로 넘침·콘솔 오류·포커스·색 대비와 자동 접근성을 검사한다. 스크린샷을 직접 검토하고 독립 리뷰의 유효한 문제를 모두 처리한다.

100% 완료는 위 항목을 모두 충족한 상태로 정의한다. 최신 최종 결과는 `docs/verification.md`에 기록한다.
